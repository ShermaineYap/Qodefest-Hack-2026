Lantern — test bench

Open this page in the Chrome profile that has the unpacked extension loaded, then work down the sections. Each click exercises a different surface: the warning page, the in-chat badge, the assistant panel, and the honest-failure path.

Every scam address here is fabricated. None of the lookalike domains resolve, and the warning page renders before any request is made, so even a mis-click loads nothing. Do not substitute a real phishing link.

0Load the extension

  • cd extension → npm install → npm run build
  • chrome://extensions → turn on Developer mode → Load unpacked → pick extension/dist
  • Pin the side panel, then confirm <API_BASE>/health returns {"status":"ok"}

If the tunnel moved, update API_BASE in extension/src/config.ts and rebuild. The current host is in server/README.md under “Deployment”.

3Assistant panel — paste a message, then press “Ask Lantern Assistant to explain”

The verdict is the demo point; wording depends on whether the tunnel runs the keyword mock or a real model. A message with a clean link can still be Unsure — that is the intended behaviour.

No link, nothing suspicious → Not a scam
Clean address → Not a scam
Clean address, uncertain message → Unsure
Red link + 24-hour pressure → Scam; open “What leaves this device” and read the request id

4Honest failure — stop the gateway

  • Stop the gateway process (or point API_BASE at an unused port and rebuild).
  • Paste a link and ask a question: both surfaces must say NOT CHECKED / “treat this as unverified”.
  • Nothing may turn green. That is the rule the whole product is built around.
